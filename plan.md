# Architecture Plan

## Overview
The backend pipeline follows a staged, unidirectional data flow architecture. It processes raw text from markdown files in an `input/` folder into styled HTML presentation files in a `slides/` folder across three distinct, loosely coupled stages. All three stages interact with the Gemini API through a shared, dependency-injected `GeminiClient` wrapper.

## Data Flow
``` text
Input Folder (*.md) 
  → [Content Generator (Gemini LLM)] 
  → SlideDeck (without images) 
  → [Image Generator (Gemini LLM)] 
  → SlideDeck (with images) 
  → [HTML Composer (Gemini LLM + file system)] 
  → Slides Folder (*.html + assets/*.jpg)
```

## Shared Types

```typescript
// src/types.ts
export interface Slide {
  title: string;
  content: string; // bullet points or body text
  speakerNotes?: string;
  imagePrompt?: string;
  imageDataBase64?: string; // Populated by Image Generator
}

export interface SlideDeck {
  slides: Slide[];
}
```

## Components

### GeminiClient Wrapper

The canonical interface that ALL stages depend on. This is the project's central contract.

```typescript
// src/geminiClient.ts
import { GoogleGenAI } from "@google/genai";

export interface GeminiClient {
  generateContent(prompt: string): Promise<string>;
  generateImageBase64(prompt: string): Promise<string>;
}

export class DefaultGeminiClient implements GeminiClient {
  private ai: GoogleGenAI;

  constructor(apiKey?: string) {
    this.ai = new GoogleGenAI({ apiKey: apiKey || process.env.GEMINI_API_KEY });
  }

  async generateContent(prompt: string): Promise<string> {
    const response = await this.ai.models.generateContent({
      model: "gemini-2.0-flash",
      contents: prompt,
    });
    return response.text || "";
  }

  async generateImageBase64(prompt: string): Promise<string> {
    const response = await this.ai.models.generateImages({
      model: "imagen-4.0-fast-generate-001",
      prompt: prompt,
      config: { outputMimeType: "image/jpeg" }
    });
    // SDK response traversal — the image bytes are nested:
    const base64Image = response.generatedImages?.[0]?.image?.imageBytes;
    if (!base64Image) {
      throw new Error("No image generated by Gemini API");
    }
    return base64Image;
  }
}
```

> [!IMPORTANT]
> The `generateImages` response shape is **non-obvious**. The bytes live at `response.generatedImages[0].image.imageBytes`, NOT at `response.images[0]` or similar. This is the `@google/genai` SDK's structure.

---

### Content Generator
- **Responsibility**: Reads one or many `.md` files from an `input/` folder, combines their content, calls the Gemini API with the canonical `CONTENT_GENERATION_PROMPT` (defined in `spec.md`) to generate a structured `SlideDeck` JSON object.
- **Input**: `string` (path to input directory) + `GeminiClient` (dependency injected)
- **Output**: `Promise<SlideDeck>`
- **Side Effects**: Reads from file system (`input/` folder) and makes network calls to the Gemini API.
- **LLM Response Handling**: The response must be trimmed and cleaned of markdown fences (`` ```json ... ``` ``) before `JSON.parse()`.
- **Testing Strategy**: Unit testing with a mocked `GeminiClient` and a mocked file system (or temp directory). Assert that Gemini receives the combined file content and returns a valid structured format. Test API failure cases.

### Image Generator
- **Responsibility**: Takes a `SlideDeck`, reads the `imagePrompt` of each slide, calls the Gemini API to generate an image, and updates the slide with `imageDataBase64`.
- **Input**: `SlideDeck` (without images) + `GeminiClient` (dependency injected)
- **Output**: `Promise<SlideDeck>` (with images populated)
- **Side Effects**: Makes network calls to the Gemini API (`@google/genai`).
- **Rate Limiting**: Accepts a `delayMs` constructor parameter (default: `6100`). Before each image API call, sleeps for `delayMs` milliseconds. Tests pass `0` to avoid slow test suites.
- **Testing Strategy**: Unit testing with a mocked `GeminiClient`. Test network failures, timeouts, and successful generations. Assert that fallback placeholder images are used on failure.

### HTML Composer
- **Responsibility**: Takes a fully populated `SlideDeck` (with images) and for each slide:
  1. Saves the Base64 image data as a file in `slides/assets/`.
  2. Calls the Gemini LLM with the canonical `HTML_GENERATION_PROMPT` (defined in `spec.md`), injecting the slide's title, content, speaker notes, image path, and slide number via `{{PLACEHOLDER}}` replacement.
  3. Strips markdown fences from the LLM response if present.
  4. Writes the LLM-generated HTML to a `.html` file in `slides/`.
  5. Falls back to a static template if the LLM call fails.
- **Input**: `SlideDeck` (with images) + `string` (path to output directory) + `GeminiClient` (dependency injected)
- **Output**: `Promise<void>`
- **Side Effects**: Writes multiple HTML and image files to the file system (`slides/` and `slides/assets/` folders). Makes network calls to the Gemini API via the injected `GeminiClient`.
- **Testing Strategy**: Unit testing with a mocked `GeminiClient` and mocked file system. Assert that the correct number of HTML and image files are written, that the HTML uses relative paths, and that the LLM output is written as-is. Test the fallback path when the API fails.

### Pipeline Orchestrator
- **Responsibility**: Wires the three stages sequentially. Creates a single `DefaultGeminiClient` and injects it into all three components. Provides console logging for progress.
- **Input**: `apiKey?: string` (constructor), `inputFolder: string`, `outputFolder: string` (run method)
- **Output**: `Promise<void>`

### CLI Entry Point
- **Responsibility**: Loads environment variables from `.env` via `dotenv`, validates `GEMINI_API_KEY` exists, reads `inputDir` and `outputDir` from `process.argv`, instantiates `Pipeline`, and calls `run()`.
- **Usage**: `npx ts-node src/index.ts [inputDir] [outputDir]` (defaults: `input`, `slides`)
- **Exit Codes**: `0` on success, `1` on error or missing API key.

## External Dependencies
- **`@google/genai`**: SDK for Gemini text generation and Imagen image generation. Wrapped in `GeminiClient` interface for mocking.
- **`dotenv`**: Loads `.env` file containing `GEMINI_API_KEY`.
- **`jest` + `ts-jest` + `jest-cucumber`**: Test runner with BDD scenario support.

## Testing Conventions
- Each `features/*.feature` file maps to a matching `src/*.test.ts` file using `jest-cucumber`'s `defineFeature(loadFeature(...))` pattern.
- Gherkin step definitions in the test file must correspond **1:1** to scenario steps in the feature file.
- External dependencies (`fs`, `GeminiClient`) are mocked via `jest.mock(...)` and dependency injection.
- The `ImageGenerator`'s `delayMs` is set to `0` in tests to avoid slow suites.
