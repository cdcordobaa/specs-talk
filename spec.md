# Feature: Backend Pipeline

## Intent
The backend pipeline processes markdown files from an `input/` folder and produces a styled HTML slide presentation with AI-generated images, outputting one `.html` file per slide in a `slides/` folder. It enables automatic conversion of simple text into comprehensive, visually engaging slide decks without manual formatting or image sourcing.

## Actors
- System / Application User (Providing raw text in markdown files)

## Constraints
- Pipeline must have three distinct stages, each a separate service with a clean contract.
- The **Content Generator** uses an LLM (Gemini via `@google/genai`) to generate the structured slide deck from one or many markdown (`.md`) files in an `input/` folder.
- The **Image Generator** uses an LLM (Gemini via `@google/genai`) to generate base64 image data from prompts.
- Both the Content Generator and Image Generator have an external dependency on the Gemini API (`@google/genai`) that must be mockable for testing.
- The Image Generator must handle failures gracefully with a fallback placeholder.
- The HTML Composer is NO LONGER a pure transformation; it must write individual HTML files to a `slides/` folder.
- Image assets must be saved as external files in an `assets/` subfolder within the `slides/` directory, and the generated HTML files must reference these assets via relative paths.
- **New Requirement**: Each slide's HTML must be generated by an LLM (Gemini) using a designer-quality prompt. The LLM receives the slide content (title, bullets, speaker notes) and the relative image path, and it must creatively design a complete, self-contained HTML slide with modern aesthetics, rich typography, and creative, varied image integration (e.g., hero, split-pane, background, inset card, etc.).
- The HTML generation prompt must be version-controlled as a constant in the `HTMLComposer` module so it can be reviewed, tested, and iterated without changing logic code.
- Strictly-typed TypeScript contracts must define the inputs and outputs between stages.

## Stages / Components
1. **Content Generator**: Reads one or many markdown files from an `input/` folder, combines them, calls the Gemini API to analyze the text, and produces a structured slide deck object containing slides with title, bullet points or body text, speaker notes, and an image prompt describing what visual would complement the content.
2. **Image Generator**: Takes the slide deck's image prompts, calls the Gemini API (`@google/genai`) to generate base64 image data, and updates the deck. Handles failures with a graceful fallback placeholder.
3. **HTML Composer**: Takes the slide deck (with images) and, for each slide, calls the Gemini LLM with a rich designer prompt to generate a visually stunning, self-contained HTML slide. The image asset is saved to `slides/assets/` and its relative path is given to the LLM so it can incorporate the image creatively (hero, background, split-pane, floating card, etc.). The result is a complete HTML file written to `slides/`.

## Acceptance Criteria
- [x] Content Generator specified in `features/content_generator.feature`
- [x] Image Generator specified in `features/image_generator.feature`
- [x] HTML Composer specified in `features/html_composer.feature`

## HTML Generation Prompt

The following prompt is the canonical version used by the HTML Composer LLM call. It must be stored as `HTML_GENERATION_PROMPT` in `src/htmlComposer.ts`:

```
You are a world-class presentation designer who writes stunning, self-contained HTML slides.

You will receive a single slide's structured data and an image path. Your task is to produce
a complete, beautiful, production-ready HTML file for that slide.

Design principles you MUST follow:
1. Modern aesthetics: rich dark or vivid color palettes, clean sans-serif typography (load from Google Fonts), smooth gradients, generous whitespace.
2. Creative image integration: do NOT just place the image below the text. Choose one of these layouts creatively based on the content:
   - Full-bleed background with text overlay and dark scrim
   - Split-pane (image left or right, content the other side)
   - Hero image at the top with bold headline below
   - Floating inset card over the image
   - Image as a textured panel or accent strip
3. The slide must feel like a premium conference presentation — NOT a basic webpage.
4. Include subtle CSS animations (fade-in, slide-up) for visual polish.
5. The image must use the EXACT relative path provided — do NOT use placeholders or data URIs.
6. Output ONLY the raw HTML. No markdown fences, no explanation text.

Slide data:
- Title: {{TITLE}}
- Content: {{CONTENT}}
- Speaker Notes (for context only, do NOT display on slide): {{SPEAKER_NOTES}}
- Image path: {{IMAGE_PATH}}
- Slide number: {{SLIDE_NUM}} of {{TOTAL_SLIDES}}
```
